# CLAUDE.md

## 1. 응답 방식

- 모든 대화, 설명, 최종 보고는 한국어로 작성한다.
- 확인한 사실, 가정, 추측을 구분하고 간결하게 설명한다.
- 실제 변경 사항과 검증 결과를 우선 보고한다.
- 오류, 미완료 사항, 실행하지 않은 검증을 숨기지 않는다.

## 2. 작업 전 판단과 범위

- 관련 코드, 호출 경로, 테스트, 설정을 확인한 뒤 구현한다.
- 요구사항이 불명확하고 결과가 달라질 수 있으면 가능한 해석과 영향을 설명하고 확인을 구한다.
- 중요한 가정은 작업 전 또는 최종 보고에 명시한다.
- 유효한 해결책이 여러 개라면 가장 단순하고 기존 코드에 잘 맞는 방법을 선택한다.
- 작업 완료 여부를 어떻게 확인할지 먼저 정리한다.
- 요청을 해결하는 데 필요한 파일과 코드만 변경한다.
- 관련 없는 리팩터링, 포맷팅, 이름 변경, 정리 작업을 하지 않는다.
- 기존 문제를 발견해도 요청 범위 밖이면 임의로 수정하지 않고 최종 보고에만 언급한다.
- 이번 변경으로 인해 새롭게 불필요해진 코드만 제거한다. 기존 미사용 코드는 임의로 삭제하지 않는다.
- 새 패턴, 추상화, 설정 옵션, 확장 지점은 현재 요구사항에 필요할 때만 추가하고, 먼저 작은 변경으로 해결할 수 있는지 검토한다.
- 중요한 설계 선택에는 Performance, Scalability, Maintainability 관점의 trade-off를 고려한다.

## 3. 구현 원칙

- 기존 프로젝트의 스타일, 구조, 네이밍, 패턴을 따른다.
- 가능한 한 작은 단위로 명확하게 변경한다.
- 오류를 숨기거나 무시하지 않는다. 빈 catch 블록, 의미 없는 예외 처리, 광범위한 예외 포착을 추가하지 않는다.
- 외부 네트워크, DB, 파일 시스템, 운영 리소스 연동은 실패 처리, 타임아웃, idempotency, 관측 가능성을 고려한다.
- Magic Number를 피하되, 테스트 상수나 명확한 도메인 상수처럼 의미가 분명한 값은 과도하게 추상화하지 않는다.
- 불필요한 의존성을 추가하지 않는다. 기존 라이브러리와 유틸리티로 해결할 수 있는지 먼저 확인한다.
- 코드 생성 도구가 관리하는 파일은 수동으로 수정하지 않는다. 필요한 경우 원본 스키마나 생성 설정을 수정한 뒤 재생성한다.
- 주석은 코드만으로 알기 어려운 이유, 제약, 부작용, 호출 순서를 설명할 때만 추가한다.
- 주석 언어는 한국어로 작성한다. 코드가 무엇을 하는지 반복하는 주석은 추가하지 않는다.

## 4. 테스트 및 검증

- 버그 수정과 동작 변경에는 가능한 한 변경을 직접 검증하는 집중된 테스트를 추가하거나 수정한다.
- 새 테스트 파일이나 큰 테스트 변경 전에는 대상 함수와 테스트 케이스 목록을 제시하고 승인받는다.
- 검증은 직접 관련 테스트 -> 모듈/패키지 테스트 -> 타입 검사 -> 린트 -> 빌드 -> 회귀 테스트 순서로 확장한다.
- 실패한 테스트를 삭제하거나 약화해서 통과시키지 않는다.
- 실행하지 않은 검증을 실행했다고 말하지 않고, 검증하지 않은 내용을 완료되었다고 주장하지 않는다.
- 최종 응답 전 diff를 검토하고 불필요한 변경을 제거한다.

## 5. Git, 명령, 보안

- 사용자 변경을 덮어쓰거나 되돌리지 않는다.
- 커밋은 명시적으로 요청받은 경우에만 실행하고, 작업 완료 시 conventional commits 형식 메시지를 제안한다.
- 커밋 메시지에 `Co-Authored-By` 트레일러를 추가하지 않는다.
- 관련 없는 변경을 커밋에 포함하지 않는다.
- 강제 푸시, 브랜치 삭제, 대량 삭제, 데이터 삭제, DB 마이그레이션, 배포는 명시적 승인 없이 수행하지 않는다.
- `sudo`, 전역 패키지 설치, 시스템 설정 변경처럼 전역 시스템에 영향을 주는 명령은 먼저 허가를 받는다.
- 비밀 정보, 인증 정보, 개인정보를 코드, 로그, 테스트, 문서, 커밋에 노출하지 않는다.
- 인증, 권한, 결제, 개인정보, 데이터 삭제 관련 변경은 보수적으로 검토하고, 안전하지 않은 요청은 위험을 설명한다.

## 6. 문서

- 공개 API, 설정 방법, 사용자 동작이 변경되면 관련 문서를 함께 수정한다.
- 문서는 실제 동작과 검증된 명령 기준으로 작성하고, 코드와 맞지 않거나 존재하지 않는 내용을 남기지 않는다.
- README나 공식 문서에 이미 있는 내용을 불필요하게 반복하지 않는다.

## 7. 최종 보고

작업을 마친 뒤 해당하는 내용을 간결하게 보고한다.

- 변경 사항과 변경 파일
- 중요한 가정과 결정 사항
- 실행한 검증 명령과 결과
- 실패했거나 생략한 검증과 이유
- 남아 있는 위험, 제한 사항, 추가 확인 사항
- 제안 커밋 메시지
